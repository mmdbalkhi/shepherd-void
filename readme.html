1. Introduction

This is the only documentation this boot stack needs. It describes, end to end, how a single Void Linux root with a Guix-installed Shepherd 0.10.5 (and a Guile 3.0.9) comes up, and how to add a new service to it.1 Why not just use Guix System’s operating-system /services? Because owning dracut -> s6 -> Shepherd explicitly makes every failure mode legible and avoids Guix SD’s implicit service graph. This repo is that explicit graph.

A machine has one service manager, not three. Here it is #4, with s6 reduced to the smallest thing that makes that possible.

guix build shepherd resolves to the store path of Shepherd; the symlink keeps /usr/local/bin/shepherd stable across profile generations. guix build See the Guix manual for details on profile generation stability.

2. The three layers

+--------------------------------------------+
|         Layer 1: dracut initramfs          |
|  hardware discovery, storage, mount root   |
+--------------------------------------------+
                     |
                     |
                     v
+--------------------------------------------+
|           Layer 2: s6-linux-init           |
|    mount @gnu, @log, mkdir control dirs    |
+--------------------------------------------+
                     |
                     |
                     v
+--------------------------------------------+
|        Layer 3: GNU Shepherd 0.10.5        |
| root-rw, pseudo-filesystems, cgroups, udev |
+--------------------------------------------+

S6’s only job is Layer 2: bring the store and runtime writable, then hand control to Shepherd with (exec). Shepherd then runs the whole graph; s6 does not manage services. 

#!/bin/sh -e
# s6 stage 0 -> Shepherd handoff.  Regenerate with:
#   s6-linux-init-maker -b /etc/s6-linux-init/skel <more options>
DISK_UUID=abcd-...

# --- 1. mount what Shepherd/store need (idempotent) ---
mountpoint -q /gnu     || mount -t btrfs -o subvol=@/@gnu,noatime /dev/disk/by-uuid/$DISK_UUID /gnu \
                       || mount -t btrfs -o subvol=@gnu,noatime       /dev/disk/by-uuid/$DISK_UUID /gnu
mountpoint -q /var/log || mount -t btrfs -o subvol=@log,noatime       /dev/disk/by-uuid/$DISK_UUID /var/log
mountpoint -q /var/tmp || mount -t btrfs -o subvol=@tmp,noatime       /dev/disk/by-uuid/$DISK_UUID /var/tmp
mountpoint -q /var/cache || mount -t btrfs -o subvol=@cache,noatime   /dev/disk/by-uuid/$DISK_UUID /var/cache

# --- 2. exec Shepherd (PID 1) ---
SHEPHERD=/usr/local/bin/shepherd    # or /gnu/current-guix-profile/bin/shepherd
[ -x "$SHEPHERD" ] || exec /sbin/agetty --noclear -a root tty1 linux
mkdir -p /run/shepherd
"$SHEPHERD" -c /etc/shepherd/init.scm -s /run/shepherd/socket \
            -l /var/log/shepherd.log -I

The generator writes current/scripts/rc.init from skel/rc.init. Edit the skel copy and re-run s6-linux-init-maker. never patch current directly.

3. Shepherd’s graph

Shepherd does not have a “boot script”. It has a dependency graph and a target symbol that means “everything that must be up”; starting that symbol resolves and runs the whole graph in parallel.

The targets live in services.d/28-boot-stages.scm 2 Shepherd has no runlevel. A stage here is a service whose #:start is (const #t) i.e. a named barrier whose only purpose is its #:requirement, so the DAG is readable from one file. See info:(shepherd)Service Types and services.d/28-boot-stages.scm. 

;; 28-boot-stages.scm --- named barriers for the boot graph.

(define boot-critical
  '(root-rw pseudo-filesystems runtime-directories
    static-device-nodes kernel-modules cgroups udev udev-settle
    file-systems tmpfs swap sysctl dmesg guix-daemon))

(define boot-ready
  '(boot-critical hostname log-files syslog random-seed
    console-setup timezone hwclock))

(define interactive
  '(boot-ready agetty-tty1 agetty-tty2 agetty-tty3
    agetty-tty4 agetty-tty5 agetty-tty6))

(define fully-online
  '(interactive loopback dbus polkit elogind seatd acpid
    network-manager zram openssh chrony))

4. Add a service (template + worked example)

Every service is a (service '(provides) #:requirement '(...) #:start ...). That is the configuration: declare what it is, what it waits on, and what it does, and never a serial start ladder.

Checklist:

  1. Add the file (zero-padded NN sorts before 28-boot-stages).
  2. Pick real provides (a list of symbols; not a string, not a list-in-a-list) and the minimal #:requirement.
  3. For daemons: argv list + #:log-file + make-kill-destructor + #:respawn? #t.
  4. For one-shots: use a pure Guile (lambda _ (zero? (system* ...))) or ~run-or-ignored~ + #:one-shot? #t + #:stop (const #t).
  5. Wire it into a stage: edit the #:requirement of interactive or fully-online’s stage in 28-boot-stages if it should be part of one.3 The stage #:requirement list is the “what must be up before X is considered up” contract. Add your symbol there to make it part of an ordered phase; leave it out and it only starts if something else pulls it in.
  6. Reload: herd load init.scm. Shepherd restarts only what changed; already-running services are untouched.

4.1. Template for daemon(ssh, etc.)

;; NN-name.scm --- one line.

;; Why it exists: <sentence>.  Why that dependency list: <edges>.
(define name
  (service '(name alias)
    #:documentation "Human sentence."
    #:requirement '(the-services-it-cannot-run-without)
    #:start  (make-forkexec-constructor '("name" "args" …)
                  #:log-file "/var/log/name.log")
    #:stop   (make-kill-destructor)
    #:respawn? #t))            ; one-shot? #t for transient steps

(register-services (list name))

4.2. Template for One-Shots (mkdir, swapon, sysctl, etc.):

;;; NN-name.scm --- one-shot setup task.

(define name
  (service '(name)
    #:documentation "Human sentence."
    #:requirement '(the-services-it-cannot-run-without)
    #:start (lambda _
              ;; Pure Guile: no shell scripts, no make-system-constructor
              (zero? (system* "command" "arg1" "arg2")))
    #:stop (const #t)
    #:one-shot? #t))

(register-services (list name))

4.3. example: syncthing as a system service (4 Syncthing is a fine fully-online citizen: network-bound, not login-critical, restart-on-crash via #:respawn? #t. The example intentionally uses the system instance; for a desktop session move it to user-shepherd, set HOME and XDG_CONFIG_HOME, and require seatd. ):

;;; 31-syncthing-example.scm --- Syncthing daemon.

;; Example service for the "how to add a service" guide in readme.org.
;; It is kept under examples/, NOT services.d/, so it is registered only when
;; you deliberately copy it in:
;;
;;   cp examples/31-syncthing-example.scm /etc/shepherd/services.d/
;;   # then add `syncthing' to the `fully-online' stage in 28-boot-stages.scm
;;   herd load init.scm
;;
;; Syncthing is a good fully-online citizen: network-bound, not login-critical,
;; and restart-on-crash via #:respawn?.  Its systemd unit ties it to
;; `network-online.target` + `local-fs.target`, which here map to
;; `network-manager` + `file-systems`.

(define syncthing
  (service '(syncthing)
    #:documentation "Syncthing file synchronizer (system instance)."
    #:requirement '(network-manager file-systems)
    #:start (make-forkexec-constructor
             '("/usr/bin/syncthing" "-no-browser" "-gui-address=0.0.0.0:8384")
             #:log-file "/var/log/syncthing.log")
    #:stop (make-kill-destructor)
    #:respawn? #t))

(register-services (list syncthing))

To enable: cp the file into /etc/shepherd/services.d/, add syncthing to the fully-online stage requirements in 28-boot-stages.scm, then herd load init.scm. A new syncthing service appears in herd status with no Shepherd restart.5 syncthing/README · its systemd unit network-online.target + local-fs.target maps exactly to network-manager + file-systems here.

Syncthing ships a systemd unit that does the same network-online + filesystem dance; this is the manual port. For a per-user GUI session, put the same service under user-shepherd/services.d/ with GUIX_PROFILE set.

5. Runtime model (what you observe at boot)

  • /etc/shepherd/init.scm loads services.d/*.scm, then (start-in-the-background '(fully-online)).
  • Shepherd resolves requirements breadth-first and starts them concurrently where the graph allows.6 start-in-the-background (from services.d/init.scm) spawns a fiber that calls start-in-parallel: each node’s #:requirement starts first, and siblings with no edge between them start concurrently. Shepherd manual §“Dependency resolution”. You see interleaved Starting service X / Service X has been started. lines in /var/log/shepherd.log.
  • A service whose #:start throws is marked failed; dependents are skipped / retried, logged, and the boot continues on other branches. one bad daemon never hangs the whole boot.7 Failures are per-service. Shepherd logs Exception caught while starting X to /var/log/shepherd.log, marks the service failed, and continues other branches rather than aborting the boot. That is intentional: a one-shot random-seed failing must not stop udev.
  • boot-ready is the barrier behind which gettys wait; fully-online is everything else that is allowed to lag.
  • On shutdown, services run their #:stop thunks in reverse-dependency order (e.g., seedrng save, hwclock --systohc, cleaning /tmp).
$ herd status                   # on the running machine
root                            (running)   uptime 00:00:47
udev                            (running)   uptime 00:00:46
syslog                          (running)   uptime 00:00:45
boot-ready                      (stopped)   start it to unblock login
agetty-tty1                     (running)   uptime 00:00:44
fully-online                    (stopped)   start it to bring the rest
$ tail -f /var/log/shepherd.log  # the spinner feeds this
2026-... Starting service udev...
2026-... Service udev has been started.

Shepherd also exposes herd = the CLI. =herd help, herd doc <service>, and [[info:(shepherd)Invoking shepherd][info:(shepherd)]] cover every flag.

7. User Shepherd (Graphical Session)

While the system Shepherd manages the machine, the User Shepherd manages your graphical session (Sway, PipeWire, D-Bus, etc.). It runs as your regular user, supervising Wayland compositors and desktop daemons without needing systemd --user.

7.1. Session Flow

  1. init.scm sets XDG_RUNTIME_DIR and DBUS_SESSION_BUS_ADDRESS.
  2. 01-runtime-dirs ensures the runtime directory exists with strict 0700 permissions.
  3. 02-dbus, 03-pipewire, and 04-gpg-agent start in parallel (no GUI dependency).
  4. 05-sway starts the compositor (depends on dbus and runtime-dirs).
  5. 06-graphical-session barrier resolves once Sway is running.
  6. ALL GUI services (dunst, portals, swayidle, clipman, etc.) start in parallel.

7.2. Installation & Bring Up

# 1. Copy user Shepherd config and services to your home directory
mkdir -p ~/.config/shepherd/services.d
cp user-shepherd/init.scm ~/.config/shepherd/init.scm
cp user-shepherd/services.d/*.scm ~/.config/shepherd/services.d/

# 2. Ensure you are in the 'seatd' group (required for Sway to access input/DRM)
sudo usermod -aG _seatd $USER
# (Log out and log back in for group changes to take effect)

# 3. Start the user Shepherd daemon
shepherd -s /run/shepherd/$(id -u).socket \
    -c ~/.config/shepherd/init.scm -I

To start User Shepherd automatically on TTY login, add this to your ~/.bash_profile or ~/.profile: if [ -z "$WAYLAND_DISPLAY" ] && [ "$XDG_VTNR" -eq 1 ]; then exec shepherd -I; fi

7.3. Managing the Session

Because every component is a first-class Shepherd service, you can manage them individually without restarting the whole session: 

# Restart just the compositor (apps using DBus/PipeWire will survive!)
herd restart sway

# Check audio stack status
herd status pipewire wireplumber pipewire-pulse

# View compositor logs
tail -f ~/.local/state/shepherd/sway.log

9. Appendix: configuration reference (source of truth)

This appendix embeds the actual Scheme configuration so this readme, carries the source of truth alongside the prose above. Each file leads with a header comment describing its role, and services carry a #:documentation string

9.1. System Shepherd entry point

(define-module (shepherd config) #:declarative? #f)
(use-modules ((ice-9 ftw) #:select (scandir))
             (srfi srfi-1))

;; Where this configuration lives.  Default to the standard location; the
;; s6 ~rc.init~ script points Shepherd here via ~-c /etc/shepherd/init.scm~.
(define %services-dir
  (or (getenv "SHEPHERD_SERVICES_DIR")
      "/etc/shepherd/services.d"))

;; 1. Load every *.scm (alphabetically) from the services directory.
;;    Each file registers its own services; ~#:requirement~ may reference a
;;    service defined in an earlier-loaded file (dependencies are resolved
;;    lazily at start time, so load order only needs shared helpers first --
;;    which is why 00-utilities.scm sorts before everything else).  The stage
;;    targets (boot-ready, interactive, fully-online, ...) live in
;;    ~28-boot-stages.scm~.
(define (load-services dir)
  (let ((files (scandir dir
                  (lambda (f)
                    (and (string-suffix? ".scm" f)
                         (not (string-prefix? "." f)))))))
    ;; Guard: warn about old-style (unnumbered) files that shadow numbered
    ;; ones.  Digits sort before letters in ASCII (0x30 < 0x61), so
    ;; 15-syslog.scm loads BEFORE socklog.scm.  The unnumbered file then
    ;; silently overrides the canonical definition -- this was the root cause
    ;; of the socklog 127 / respawn-too-fast cascades on the Void host.
    (let ((stale (filter (lambda (f)
                           (not (char-numeric? (string-ref f 0))))
                         files)))
      (when (pair? stale)
        (format #t "WARNING: old-style (unnumbered) service files shadow numbered files:\n  ~a\nThese load AFTER the numbered files and silently override them.\nRemove them: rm ~a/*.scm (the unnumbered ones)\n\n"
                (string-join stale ", ") dir)))
    (for-each
     (lambda (file)
       (load (string-append dir "/" file)))
     files)))

(load-services %services-dir)

;; 2. Self-check policy.
;;    Shepherd 0.10.x exposes no public "list all services" API from a config
;;    file (the registry is channel-based and private), so a static
;;    "missing-requirements" scan cannot be done here inline.  Instead:
;;      * graph integrity (no cycles, no dangling requirements) is verified by
;;        the off-line validator (~validate-guile.scm~), run by the author;
;;      * at boot, ~start-in-the-background~ resolves the ~fully-online~ graph
;;        and Shepherd throws/logs an ~unresolved requirement' (or
;;        ~Unregistered service') to /var/log/shepherd.log for any symbol that
;;        is required but never provided -- i.e. boot still fails fast and
;;        loud, just one layer inside the daemon.
;;    This keeps init.scm free of version-coupled internal accessors.

;; 3. Kick off boot by resolving the ~fully-online~ target's graph.  Placed at
;;    the end of init.scm on purpose: Shepherd evaluates this file once at
;;    startup (launched from s6 stage 0) and starts the machine.  ~start-in-the
;;    background' returns immediately so the control socket is served right
;;    away; already-running services are left untouched on a later
;;    ~herd load init.scm~.  (shepherd/service) exports start-in-the-background,
;;    NOT a bare ~start'.
(unless (equal? (getenv "SHEPHERD_NO_AUTOBOOT") "1")
  (start-in-the-background '(fully-online)))

9.2. System service definitions

;;; 00-utilities.scm --- shared helpers (loaded first; registers nothing).
;; Because ~scandir~ in init.scm loads every *.scm file, these helpers are
;; available to every service below.  They encode the small, repeated pieces
;; (mount-option formatting, idempotent mountpoint checks) so that individual
;; service files read like declarative data, not shell.

(use-modules (srfi srfi-1) ; filter
             (shepherd service))

(define (opts->string opts)
  "Render ~('nosuid', 'nodev', ...)~ as ~-o nosuid,nodev~.
The empty / ~('default')~ list renders as ''."
  (if (or (null? opts) (equal? opts '("defaults")))
      ""
      (string-append " -o " (string-join opts ","))))

(define (mountpoint-q? target)
  "Return #t when TARGET is already a mount point."
  (zero? (system (string-append "mountpoint -q " target))))

(define (ensure-dir dir)
  "Create DIR and parents."
  (zero? (system* "mkdir" "-p" dir)))

(define (run-or-ignored command . args)
  "Run the primitive COMMAND (an absolute path) with ARGS, treating absence or
a non-zero exit as success -- i.e. the Scheme equivalent of the shell idiom
~(command ... 2>/dev/null || true)' used for best-effort one-shots such as
swapon or seedrng.  Returns a truthy value so Shepherd records success."
  (catch 'system-error
    (lambda () (apply system* command args))
    (lambda _ #t)))

(define (mounted? dir)
  (catch 'system-error
    (lambda ()
      (let ((st-dir (stat dir))
            (st-parent (stat (dirname dir))))
        (not (= (stat:dev st-dir) (stat:dev st-parent)))))
    (lambda args
      ;; If the directory doesn't exist yet, it's not mounted.
      #f)))

(define* (pseudo-fs-service name
                            #:key
                            source
                            target
                            type
                            (options '())
                            (requirement '()))
  (service
   (list name)
   #:documentation
   (format #f "Mount pseudo-filesystem ~a on ~a~a."
           type target
           (if (null? options) ""
               (format #f " (options: ~{~a~^,~})" options)))
   #:requirement requirement
   #:start
   (lambda _
     ;; Build the mount command arguments purely as a Scheme list.
     (let ((args (append `("-t" ,type)
                         (if (null? options)
                             '()
                             `("-o" ,(string-join options ",")))
                         `(,source ,target))))
       ;; Attempt to mount. If it fails, check if it's already mounted.
       ;; This makes the service perfectly idempotent without shell scripts.
       (or (zero? (apply system* "mount" args))
           (mounted? target))))
   #:stop (const #t)
   #:one-shot? #t))

;; A descriptive, non-working target service grouping several requirements.
;; Used purely to give the boot graph readable named layers.
(define* (stage name documentation requirements)
  ;; If name is already a list, use it; otherwise, wrap the symbol in a list.
  (service (if (list? name) name (list name))
           #:documentation documentation
           #:requirement requirements
           #:start (const #t)
           #:stop (const #t)
           #:one-shot? #t))

(define (read-rc-conf-var var)
  "Read a variable from /etc/rc.conf (e.g., KEYMAP='us')."
  (catch 'system-error
    (lambda ()
      (call-with-input-file "/etc/rc.conf"
        (lambda (port)
          (let loop ((line (read-line port)))
            (cond
             ((eof-object? line) #f)
             ((string-prefix? (string-append var "=") (string-trim-both line))
              (let* ((val (substring line (+ (string-length var) 1)))
                     (val (string-trim-both val)))
                ;; Strip surrounding quotes if present
                (if (and (>= (string-length val) 2)
                         (char=? (string-ref val 0) #\")
                         (char=? (string-ref val (- (string-length val) 1)) #\"))
                    (substring val 1 (- (string-length val) 1))
                    val)))
             (else (loop (read-line port))))))))
    (lambda args #f)))

;;; 04-cgroups.scm --- cgroup hierarchy mounting.

;; The old setup shipped a large shell block switching on CGROUP_MODE in the
;; middle of a ~while read~ loop over /proc/cgroups.  Here the mode decision
;; and the controller enumeration live in Scheme; only each individual ~mount~
;; is a single small shell command guarded by an idempotency check.

(use-modules (srfi srfi-1)   ; filter, filter-map
             (shepherd service))

;; mkdir-p is NOT exported by (ice-9 ftw) in Guile 3.0.9 from Guix store.
;; Use system* "mkdir" "-p" instead — this is the robust, portable approach.
(define (ensure-dir dir)
  (zero? (system* "mkdir" "-p" dir)))

(define %cgroup-mode
  ;; Mirrors Void's /etc/rc.conf CGROUP_MODE (default: unified; this box).
  (or (getenv "CGROUP_MODE") "unified"))

(define (mountpoint-q? target)
  (zero? (system (string-append "mountpoint -q " target))))

(define (enabled-cgroup-v1-controllers)
  "Return the names of cgroup v1 controllers flagged ~enabled=1~ in
/proc/cgroups.  Returns the empty list when the file is absent."
  (catch 'done
    (lambda ()
      (let ((port (false-if-exception (open-input-file "/proc/cgroups"))))
        (if port
            (let ((lines '()))
              (do ((line (get-line port) (get-line port)))
                  ((eof-object? line) (set! lines (reverse lines)))
                (set! lines (cons line lines)))
              (close-input-port port)
              (filter-map
               (lambda (line)
                 (let ((f (filter (lambda (s) (not (string=? s "")))
                                  (string-split line char-whitespace))))
                   (and (>= (length f) 4)
                        (string=? (cadddr f) "1")
                        (car f))))
               lines))
            (throw 'done '()))))
    (lambda _ '())))

(define (mount-node type source target opts)
  "Mount a cgroup node, idempotently: skip when already a mount point."
  (unless (mountpoint-q? target)
    (ensure-dir target)
    (system (string-append "mount -t " type
                           (if (null? opts) ""
                               (string-append " -o " (string-join opts ",")))
                           " " source " " target))))

(define (cgroup2-boot)
  "Mount the cgroup v2 hierarchy on unified and hybrid modes (no-op legacy)."
  (when (not (string=? %cgroup-mode "legacy"))
    (mount-node "cgroup2" "cgroup2" "/sys/fs/cgroup" '("nsdelegate"))))

(define (cgroup-v1-boot)
  "Mount cgroup v1 tmpfs + per-controller hierarchies (legacy/hybrid only)."
  (when (member %cgroup-mode '("legacy" "hybrid"))
    (unless (mountpoint-q? "/sys/fs/cgroup")
      (ensure-dir "/sys/fs/cgroup")
      (system "mount -t tmpfs cgroup_root /sys/fs/cgroup"))
    (for-each
     (lambda (controller)
       (mount-node "cgroup" controller
                   (string-append "/sys/fs/cgroup/" controller) '()))
     (enabled-cgroup-v1-controllers))
    ;; systemd-tracking cgroup, for nested systemd instances.
    (mount-node "cgroup" "none,name=systemd" "/sys/fs/cgroup/systemd" '())))

(define cgroup2
  (service '(cgroup2 cgroup-hierarchy)
           #:documentation "Mount the cgroup v2 hierarchy at /sys/fs/cgroup."
           #:requirement '(sys runtime-directories)
           #:start (lambda _ (cgroup2-boot) #t)
           #:stop (const #t)
           #:one-shot? #t))

(define cgroup-v1
  (service '(cgroup-v1)
           #:documentation
           "Mount cgroup v1 hierarchies (legacy/hybrid only; no-op on unified)."
           #:requirement '(sys runtime-directories cgroup2)
           #:start (lambda _ (cgroup-v1-boot) #t)
           #:stop (const #t)
           #:one-shot? #t))

;; Descriptive overlay: the single ~cgroups~ name referenced by boot-ready.
(define cgroups
  (stage 'cgroups "cgroup hierarchies are in place." '(cgroup2 cgroup-v1)))

(register-services (list cgroup2 cgroup-v1 cgroups))

;;; 14-log-files.scm --- utmp/wtmp/btmp/lastlog + socklog spool + dirs.

;; based on runit/core-services/99-cleanup.sh
;; Creates the accounting and log scaffolding.  Per-service logs are written by
;; Shepherd to their own ~#:log-file~ (and Shepherd auto-creates the parent
;; dir on first write), so here we only lay out the system-wide log/utmp
;; files and the socklog spool directories with their syslog ~config~ files.
;;
;; socklog reads its per-facility ~config~ using svlogd directives:
;;   s<size>  rotate at <size> bytes
;;   n<count> keep <count> rotated files
;;   -*       clear the accept list
;;   +pat     accept messages matching pat

(use-modules (srfi srfi-13) ;; string things
             )

(define log-files
  (service '(log-files utmp)
           #:documentation "Create utmp/wtmp/btmp/lastlog and the socklog spool."
           #:requirement '(root-rw file-systems runtime-directories)
           #:start (lambda _
                     ;; 1. Create the utmp/wtmp/btmp/lastlog files
                     (for-each (lambda (args) (apply system* args))
                               '(("install" "-m0664" "-o" "root" "-g" "utmp" "/dev/null" "/run/utmp")
                                 ("install" "-m0664" "-o" "root" "-g" "utmp" "/dev/null" "/var/log/wtmp")
                                 ("install" "-m0600" "-o" "root" "-g" "utmp" "/dev/null" "/var/log/btmp")
                                 ("install" "-m0600" "-o" "root" "-g" "utmp" "/dev/null" "/var/log/lastlog")))

                      ;; 2. Boot marker in /var/log/wtmp (so `last` shows the boot).
                      ;;    Void's `halt -B' idiom is unsafe here: on this host
                      ;;    /bin/halt is a `herd` proxy that *reboots* (and now
                      ;;    that /usr/local/bin is on PATH at boot, `halt -B`
                      ;;    would actually trigger a reboot during boot).
                      ;;    Writing a wtmp BOOT_TIME record needs a proper utmp
                      ;;    writer (pututxline/utmpdump); until one is wired in,
                      ;;    skip it rather than risk a boot-time reboot.
                      ;;    (See services.d/29-power.scm for the real shutdown.)

                     ;; 3. socklog spool setup
                     (system* "mkdir" "-p" "/var/log/socklog")
                     (system* "chown" "root:socklog" "/var/log/socklog")
                     (system* "chmod" "2750" "/var/log/socklog")
                     (for-each (lambda (facility)
                                 (let ((dir (string-append "/var/log/socklog/" facility)))
                                   (system* "mkdir" "-p" dir)
                                   (call-with-output-file (string-append dir "/config")
                                     (lambda (port)
                                       (display "s1000000\nn10\n" port)))
                                   (system* "chown" "root:socklog" dir)
                                   (system* "chmod" "0750" dir)))
                               '("messages" "daemon" "cron"))
                     #t)
           #:stop (lambda _
                    ;; Shutdown cleanup (replaces Void's 99-cleanup.sh)
                    (for-each (lambda (args)
                                (unless (file-exists? (last args))
                                  (apply system* args)))
                              '(("install" "-m0664" "-o" "root" "-g" "utmp" "/dev/null" "/var/log/wtmp")
                                ("install" "-m0600" "-o" "root" "-g" "utmp" "/dev/null" "/var/log/btmp")

;;; 28-boot-stages.scm --- boot barriers and stage targets.

;; Three descriptive stage targets, plus the ~boot-ready~ barrier that gates the
;; interactive gettys. These targets perform no work themselves: their only job
;; is to express ordering through ~#:requirement~ so that the graph is obvious
;; from reading this file.
;;
;;   boot-critical : everything needed to run the store / devices.
;;   boot-ready    : the subset of the above that login actually waits on.
;;   interactive   : virtual terminals.
;;   fully-online  : networking + desktop/session daemons.
;;
;; =agetty= depends on =boot-ready= (NOT on a serial list), so unrelated
;; boot-critical services run in parallel and never block each other.

(use-modules (shepherd service))

;; boot-critical: The absolute minimum to get the kernel, storage, and
;; pseudo-filesystems ready.  guix-daemon is NOT here: on a foreign distro
;; (Void) the Guix store libraries live in /gnu/store/* and a
;; garbage-collected dependency causes exit 127.  Since Shepherd is the
;; only Guix component needed at boot, guix-daemon was moved to
;; ~fully-online~ and made non-respawning (see 16-guix-daemon.scm).
(define boot-critical
  (stage 'boot-critical "Stage 1: core system initialization."
         '(root-rw pseudo-filesystems runtime-directories
           static-device-nodes kernel-modules cgroups udev udev-settle
           file-systems tmpfs swap sysctl dmesg)))

;; boot-ready: The barrier behind which gettys wait.
;; Includes user-facing setup like console, timezone, and hwclock.
(define boot-ready
  (stage 'boot-ready "Barrier: root, devices, filesystems, hostname, logging,
and console are ready. Gettys may start once this is up."
         '(boot-critical hostname log-files syslog random-seed
           console-setup timezone hwclock)))

;; interactive: Things that require a TTY or user session.
(define interactive
  (stage 'interactive "Stage 2: local TTYs and user login."
         '(boot-ready agetty-tty1 agetty-tty2 agetty-tty3
           agetty-tty4 agetty-tty5 agetty-tty6)))

;; fully-online: Network and background daemons.
(define fully-online
  (stage 'fully-online "Stage 3: networking, D-Bus, seat/session, SSH, and friends.
These deliberately do NOT gate the gettys."
          '(interactive loopback dbus polkit elogind seatd acpid
                        network-manager zram openssh chrony guix-daemon)))

(register-services (list boot-critical boot-ready interactive fully-online))

;;; 29-power.scm --- reboot and halt targets for Shepherd.

;; Since s6-linux-init-hpr no longer works (Shepherd replaced it as PID 1),
;; we define native Shepherd targets that drive the Magic SysRq keys directly.
;;
;; IMPORTANT ordering: the old implementation ran `umount -a -r` *before*
;; triggering SysRq.  That unmounted /run, which deleted the shepherd socket
;; ("Socket deleted; stopping") and killed shepherd, and *then* fired the
;; reboot -- so if the SysRq key never took effect the box was left half-dead
;; with no supervisor.  SysRq 'b'/'o' reboot/halt the kernel immediately and
;; skip the unmount, so we trigger it FIRST (after sync+remount-ro via
;; 's'/'u') and let the kernel tear the filesystems down.

(define (sysrq . keys)
  "Write each KEY to /proc/sysrq-trigger, silently ignoring failures (e.g.
when SysRq is disabled or unavailable to this build)."
  (for-each
   (lambda (key)
     (false-if-exception
      (let ((fd (open-file "/proc/sysrq-trigger" "w")))
        (display key fd)
        (close-port fd))))
   keys))

(define reboot
  (service '(reboot)
           #:documentation "Reboot the machine via the Magic SysRq sequence."
           #:requirement '(root-rw)
           #:start (lambda _
                     (sync)
                     (sysrq "s" "u" "b")   ; sync, remount-ro, reboot
                     #t)
           #:one-shot? #t))

(define halt
  (service '(halt poweroff)
           #:documentation "Power off / halt the machine via the Magic SysRq sequence."
           #:requirement '(root-rw)
           #:start (lambda _
                     (sync)
                     (sysrq "s" "u" "o")   ; sync, remount-ro, poweroff
                     #t)
           #:one-shot? #t))

(register-services (list reboot halt))

;;; User Shepherd config (copy to ~/.config/shepherd/init.scm).
;;
;; Run as the regular user with:
;;   guix package -i shepherd
;;   mkdir -p ~/.config/shepherd
;;   cp -r ~/.dotfiles/shepherd/user-shepherd/services.d \
;;         ~/.config/shepherd/services.d
;;   cp ~/.dotfiles/shepherd/user-shepherd/init.scm \
;;         ~/.config/shepherd/init.scm
;;   shepherd -s /run/shepherd/$(id -u).socket \
;;       -c ~/.config/shepherd/init.scm -I
;;
;; Expects:
;;   * a system seatd socket at /run/seatd/socket (the root `seatd` service
;;     in Stage 3; this user must be in the `_seatd' group:
;;     usermod -aG _seatd $USER)
;;   * xbps packages installed (see "Required xbps packages" below)
;;   * XDG_RUNTIME_DIR=/run/user/$UID (elogind on the system side creates it
;;     via PAM when you log in on an agetty with elogind running).
;;
;; Session flow:
;;   Shepherd starts -> loads services.d/*.scm
;;     -> runtime-dirs sets up XDG_RUNTIME_DIR + DBUS_SESSION_BUS_ADDRESS
;;     -> dbus, gpg-agent, pipewire start in parallel
;;     -> sway starts
;;       -> graphical-session barrier becomes ready
;;       -> ALL GUI services start in parallel (dunst, swayidle, portals, etc.)
;;     -> sway-session barrier resolves
;;   `herd restart sway` / `herd restart pipewire` / etc. all work.

(define-module (shepherd config)
              #:declarative? #f)
(use-modules (shepherd service)
             ((ice-9 ftw) #:select (scandir)))

;; Ensure runtime environment is set *before* loading service files, so that
;; base-env() in 00-utilities.scm captures DBUS_SESSION_BUS_ADDRESS.
(let ((rt (or (getenv "XDG_RUNTIME_DIR")
              (string-append "/run/user/" (number->string (getuid))))))
  (unless (getenv "XDG_RUNTIME_DIR")
    (setenv "XDG_RUNTIME_DIR" rt))
  (unless (getenv "DBUS_SESSION_BUS_ADDRESS")
    (setenv "DBUS_SESSION_BUS_ADDRESS"
            (string-append "unix:path=" rt "/bus"))))

(define %services-directory
  (or (getenv "SHEPHERD_USER_SERVICES")
      (string-append (or (getenv "HOME") "/home/komeil")
                     "/.config/shepherd/services.d")))

;; 1. Load every *.scm (alphabetically) from the services directory.
;;    Each file registers its own services; #:requirement may reference a
;;    service defined in an earlier-loaded file (resolved lazily at start
;;    time).  00-utilities.scm sorts first so helpers are available.
(for-each
 (lambda (file)
   (load (string-append %services-directory "/" file)))
 (scandir %services-directory
          (lambda (f)
            (and (string-suffix? ".scm" f)
                 (not (string-prefix? "." f))))))

;; 2. Top-level barrier: the complete user graphical session.
;;    Its #:requirement pulls in every branch of the graph; Shepherd resolves
;;    them in parallel where the DAG allows.
(define sway-session
  (service '(sway-session desktop graphical-session-user)
           #:documentation
           "Barrier: the complete user graphical session (dbus, audio,
gpg-agent, sway, and all GUI daemons)."
           #:requirement '(dbus pipewire gpg-agent sway graphical-session)
           #:start (const #t)
           #:stop (const #t)
           #:one-shot? #t))

(register-services (list sway-session))

;; 3. Kick off the session.
;;    (shepherd service) exports start-in-the-background, not a bare start.
;;    Resolves the graph and starts services concurrently where possible.
(start-in-the-background '(sway-session))

;; mkdir-p: create DIR and parents. Defined locally to avoid depending on
;; (ice-9 ftw) availability variations across some Guile builds.
(define* (mkdir-p dir #:optional (mode #o755))
  (let loop ((parts (string-split dir #\/))
             (path ""))
    (if (null? parts)
        #t
        (let* ((next (car parts))
               (full (if (string=? path "") next
                         (string-append path "/" next))))
          (unless (or (string=? next "") (file-exists? full))
            (catch 'system-error
              (lambda () (mkdir full mode))
              (lambda args
                ;; If the error is not EEXIST, re-throw it.
                (unless (= (system-error-errno args) EEXIST)
                  (apply throw args)))))
          (loop (cdr parts) full)))))

(define* (binary name #:optional (hint ""))
  "Resolve an xbps-installed binary by trying common prefixes.
Returns the first existing path, or NAME if none found (so Shepherd
logs a clear 'No such file or directory' error rather than silently
resolving to PATH)."
  (let ((candidates
         (append
          (if (string=? hint "")
              '()
              (list (string-append hint "/" name)))
          (list (string-append "/usr/bin/" name)
                (string-append "/usr/sbin/" name)
                (string-append "/usr/libexec/" name)
                (string-append "/usr/lib/" name)
                (string-append "/bin/" name)))))
    (or (find file-exists? candidates)
        name)))

#!/usr/bin/bash
#
# s6-linux-init stage-0 -> Shepherd handoff.
#
# This file lives in the s6-linux-init *skeleton* (skel/rc.init), not in
# `current/scripts/`.  Regenerate with:
#   s6-linux-init-maker -b /etc/s6-linux-init/skel ...
# s6-linux-init-maker copies it to current/scripts/rc.init, so edits here
# survive rebuilds.
#
# This script does THREE things and no more:
#   1. mount /gnu, /var/log, /var/tmp (the minimal set Shepherd + the store
#      need before it can run), mount a fresh tmpfs on /run, and create the
#      runtime tree (/run/shepherd, /var/log/shepherd).  /var/cache is NOT
#      mounted here (xbbs cache only, @pkg subvol); fstab handles it.
#   2. launch the Shepherd daemon (init.scm then drives the whole graph via
#      its dependency requirements).
#   3. tail Shepherd's logfile to the console with a colored spinner.
# Nothing past this point is managed by s6 -- Shepherd owns udev, dbus,
# networking, gettys, sway, etc.
#
# NOTE: s6-linux-init supervises this stage-1 script but does NOT supervise
# the Shepherd daemon launched here -- Shepherd is bg'd and orphaned.  If it
# ever exits, the socket disappears and stays gone until the next boot, so
# `herd' reports "no socket".  Keep boot steps below from deleting /run.
set -Eeuo pipefail

# /usr/local/bin holds the `herd` and `shepherd` symlinks (into /gnu/store).
# Services launched by Shepherd inherit this PATH; without it any service that
# shells out to `herd` fails at boot (e.g. the old `halt -B' boot-marker).
export PATH=/usr/local/sbin:/usr/local/bin:/usr/bin:/usr/sbin:/sbin:/bin

# Optionally pull in the live Guix profile so daemons/tools upgraded later via
# `guix package` are visible to services launched further down.  Non-fatal: the
# /usr/local/bin shim above already guarantees `herd' is resolvable when
# s6-linux-init itself runs.  /run/current-guix-profile may not exist yet this
# early (activation creates it); sourcing a missing script is skipped.
if [ -r /etc/profiles/guix.sh ]; then
    # shellcheck disable=SC1091
    . /etc/profiles/guix.sh 2>/dev/null || \
        echo "rc.init: warning: /etc/profiles/guix.sh failed to source" >/dev/console 2>/dev/null || true
fi

rl="${1:-default}"
[ $# -gt 0 ] && shift || true

DISK_UUID=bded8bd1-ce84-47a6-8a90-0d0495f68111
LOGFILE=/var/log/s6-shepherd-boot.log
CONSOLE_LOGLEVEL=4
if grep -q 'loglevel=[7-9]' /proc/cmdline 2>/dev/null; then
    CONSOLE_LOGLEVEL=7
fi

# verbose + strict logger: always appends to $LOGFILE, prints color to /dev/console.
# usage: log <level> <msg>
log() {
    local level="${1:-info}" msg="$2" color=""
    case "$level" in
    critical|error) color='\033[1;31m';;
    warn)           color='\033[1;33m';;
    debug)          color='\033[0m'; [ "$CONSOLE_LOGLEVEL" -ge 7 ] || return 0;;
    info)           color='\033[1;32m'; [ "$CONSOLE_LOGLEVEL" -ge 6 ] || return 0;;
    *)              color='\033[0m';;
    esac
    printf '%s [%s] %s\n' "$(date '+%Y-%m-%d %H:%M:%S')" "$level" "$msg" >>"$LOGFILE" 2>/dev/null || true
    printf "${color}%s\033[0m\n" "$msg" >/dev/console 2>/dev/null || true
}

# Diagnostic: confirm rc.init is running (bypasses _log which needs /var/log)
echo "rc.init: starting (rl=$rl)" >/dev/console 2>/dev/null || true
log info "rc.init start rl=$rl (PATH=$PATH)"

# 1a. /var/log (persistent, btrfs subvol so crash logs survive reboot)
mkdir -p /var/log
mountpoint -q /var/log 2>/dev/null || \
    mount -t btrfs -o subvol=@log,noatime "/dev/disk/by-uuid/$DISK_UUID" /var/log \
    || log warn "/var/log mount failed (using existing)"

# 1b. /var/tmp
mkdir -p /var/tmp
mountpoint -q /var/tmp 2>/dev/null || \
    mount -t btrfs -o subvol=@/@tmp,noatime "/dev/disk/by-uuid/$DISK_UUID" /var/tmp \
    || log warn "/var/tmp mount failed (using existing)"

# 1c. /gnu -- the store.  No /gnu, no Shepherd; this is the hard gate.
mkdir -p /gnu
if ! mountpoint -q /gnu 2>/dev/null; then
    if ! mount -t btrfs -o subvol=@/@gnu,noatime "/dev/disk/by-uuid/$DISK_UUID" /gnu; then
        log critical "CRITICAL: /gnu mount failed"
        exec /sbin/agetty --noclear -a root tty1 linux
    fi
fi
log info "/gnu ok"

# 1d. /run -- fresh tmpfs each boot.  This is the key fix for "Socket deleted;
#     stopping": /run is recreated empty and deterministic, and we never umount
#     it from a service.  Idempotent: only mount/mkdir/chmod if not already done.
mkdir -p /run
mountpoint -q /run 2>/dev/null || \
    mount -t tmpfs -o mode=0755,nosuid,nodev tmpfs /run \
    || log warn "/run tmpfs mount failed (proceeding with existing /run)"
ln -sfnT /run /var/run 2>/dev/null || true
mkdir -p /run/shepherd
chmod 700 /run/shepherd
# /var/log/shepherd holds per-service logs Shepherd's logger pulls here.
mkdir -p /var/log/shepherd

# Ensure the `socklog` group exists before Shepherd starts its services:
# 14-log-files.scm chowns the /var/log/socklog spool to root:socklog, and
# without this group every boot logs `chown: invalid group: 'root:socklog'`.
getent group socklog >/dev/null 2>&1 || groupadd -r socklog 2>/dev/null || log warn "could not create 'socklog' group"

log info "rc.init stage-0 complete, launching Shepherd"

# 1e. /sbin is not where `herd' lives; add it to the boot PATH.
SHEPHERD=/usr/local/bin/shepherd
[ -x "$SHEPHERD" ] || SHEPHERD=/gnu/current-guix-profile/bin/shepherd
if [ ! -x "$SHEPHERD" ]; then
    log critical "CRITICAL: no shepherd binary found"
    exec /sbin/agetty --noclear -a root tty1 linux
fi
log info "Using $SHEPHERD"

# 1f. Launch Shepherd once. -I = stay in foreground (we bg it); -s socket,
#     -c config, -l daemon log. Idempotent: skip if a socket is already live.
if [ ! -S /run/shepherd/socket ]; then
    "$SHEPHERD" -s /run/shepherd/socket -c /etc/shepherd/init.scm \
        -l /var/log/shepherd.log -I >/dev/null 2>&1 &
    i=0
    while [ ! -S /run/shepherd/socket ] && [ "$i" -lt 150 ]; do
        sleep 0.1
        i=$((i + 1))
    done
fi

if [ ! -S /run/shepherd/socket ]; then
    log critical "CRITICAL: shepherd socket not created"
    log critical "--- /var/log/shepherd.log ---"
    tail -n 40 /var/log/shepherd.log >>"$LOGFILE" 2>/dev/null || true
    log critical "Falling back to emergency getty"
    exec /sbin/agetty --noclear -a root tty1 linux
fi
log info "SUCCESS: shepherd up, config loaded"

# 1g. Mirror Shepherd's lifecycle log to the console with a colored spinner.
(
    set -e
    current_svc=""
    spinner_pid=""

    spin() {
        local svc="$1" i=0 chars='-\|/'
        while true; do
            printf '\r\033[0;36m→ Starting %-20s %s\033[0m' \
                "$svc" "${chars:$i:1}" >/dev/console 2>/dev/null || true
            i=$(( (i + 1) % 4 ))
            sleep 0.1
        done
    }

    tail -n 0 -F /var/log/shepherd.log 2>/dev/null |
    while IFS= read -r line; do
        case "$line" in
        *"Starting service "*)
            if [ -n "$spinner_pid" ]; then kill "$spinner_pid" 2>/dev/null || true; fi
            wait "$spinner_pid" 2>/dev/null || true
            current_svc=$(printf '%s' "$line" | sed -n 's/.*Starting service \([^.]*\).*/\1/p')
            spin "$current_svc" &
            spinner_pid=$!
            ;;
        *"has been started."*)
            if [ -n "$spinner_pid" ]; then kill "$spinner_pid" 2>/dev/null || true; fi
            wait "$spinner_pid" 2>/dev/null || true
            spinner_pid=""
            printf '\r\033[1;32m✓ Service %-20s started\033[0m\n' \
                "$(printf '%s' "$line" | sed -n 's/.*Service \([^ ]*\) has been started.*/\1/p')" >/dev/console 2>/dev/null || true
            ;;
        *"has been disabled."*|*"failed to start"*|*"Respawning too fast"*|*"is currently disabled."*)
            if [ -n "$spinner_pid" ]; then kill "$spinner_pid" 2>/dev/null || true; fi
            wait "$spinner_pid" 2>/dev/null || true
            spinner_pid=""
            printf '\r\033[1;31m✗ Service %-20s failed\033[0m\n' \
                "$(printf '%s' "$line" | sed -n 's/.*Service \([^ ]*\).*/\1/p')" >/dev/console 2>/dev/null || true
            ;;
        esac
    done
) &

log info "rc.init finished OK"
